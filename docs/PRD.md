## 1. 背景

专利挖掘常见的失败方式，是从产品文档直接生成一篇申请文件。中间缺少可回溯的技术事实、可独立评估的发明点，以及人和模型分工明确的决定。结果是权利要求与真实方案脱节，新颖性和创造性经不起对比文献，说明书也无法支持权利要求。

PatentX 把「开发挖掘」和「撰写」放在同一条案件上。挖掘产出结构化对象，撰写消费这些对象，审查结论写回同一份状态，供下一轮挖掘继续使用。

## 2. 产品定位

PatentX 是面向专利代理人与企业知识产权工程师的撰写工作台，只处理软件类发明专利。一次专利申请对应一个案件（Case）。运行内核是一个 harness Agent，它管理多个会话：一个会话绑定一个 Case，同一时刻只有一个会话处于激活状态。案件状态、长期记忆、阶段门禁和工具边界由 harness 持有，模型在激活会话内读取该 Case 的状态与记忆摘要、调用工具、写回结构化对象。

工作台页面是案件状态的投影。页上的按钮与对话里的 Agent 调用同一组工具，不另开旁路改数据。切换会话等于切换当前 Case，激活会话的上下文随之整体替换。

## 3. 目标用户与场景

**知识产权工程师。** 从研发材料中划定挖掘范围，抽出技术特征，聚合成发明点，并决定撰写、补实验、转为技术秘密或放弃。

**专利代理人。** 在已确认的发明点和评估记录上撰写交底书与申请文件，按三性 review 的退回动作改范围、补实施方式。

**发明人。** 确认替代方案是否可实施、效果是否有据，并关闭交底书中的开放问题。

典型场景：一项在研软件需要一轮专利挖掘。工程师划定模块边界并导入设计说明、流程和代码材料；工作台抽出技术特征并聚合成发明点；三性 review 给出初判；人做出处置；通过的发明点进入交底和撰写；定稿前再跑一次三性；定稿后已保护特征与未覆盖特征写回特征库。

## 4. 产品原则

1. 对象先于长文。阶段之间传递范围卡、技术特征、发明点、评估记录、交底书、申请文件和布局地图，而不是一篇自由文本。
2. 出处先于发明点。没有出处的内容只能标为待核实，不能进入发明点。
3. 决定权在人。模型起草区别特征、交底段落和权利要求。处置结论、保护范围和三性放行由人确认。
4. 撰写与 review 分离。撰写 Agent 不能把自己产出的三性结论标为通过。
5. 门禁由 harness 执行。不满足不变量的写回直接拒绝，案件停在当前阶段。
6. 定稿回写特征库。下一轮挖掘从已保护特征和未覆盖特征继续，而不是重新阅读全部原文。
7. 会话与案件一一对应。Agent 可以同时持有多个会话，但一次写回只落在当前激活的 Case 上。等待人工决定的会话保持挂起，不挡住其他案件继续推进。
8. 每个 Case 自创建起就有长期记忆。记忆跟着案件走，不跟着某一次对话窗口走。切换、挂起、恢复、上下文压缩和会话结束都不清除它。
9. 只做发明专利，且全部是软件专利。案件不能建成实用新型或外观设计。保护对象是软件实现的技术方案，不是产品外观或界面视觉样式。
10. 用户的主路径是和 Agent 的会话，交互方式对齐 Codex：左侧会话列表，中间对话流，底部输入框，右侧是当前案件产物。阶段推进和人工确认都发生在这条对话里。

## 5. 内核：Harness Agent

### 5.1 职责划分

**Harness** 持有会话表和其中每个 Case 的全部对象、长期记忆、当前阶段、待办和人工决定。它决定激活会话在本阶段可以调用哪些工具，校验每次写回的结构，检查门禁，并在需要人决定时挂起该会话的循环。

**Agent** 读取 harness 注入的会话列表摘要，以及激活会话的当前阶段、未完成门禁、对象摘要和该 Case 的记忆摘要。它选择一个当前允许的工具，根据工具结果继续、召回更早的记忆、切换会话或停止。

### 5.2 会话与 Case

会话是 Agent 循环的运行单元，Case 是专利事项的持久状态。二者一一对应：创建一个 Case 就创建一个会话，关闭会话不删除 Case。

会话状态取值为：

| 状态 | 含义 |
|---|---|
| 进行中 | 当前激活，Agent 循环可继续调用该 Case 的阶段工具 |
| 待人决定 | 门禁挂起，循环停止，等待对应角色提交决定 |
| 待命 | 已保存进度，未被激活 |
| 已结束 | Case 已完成回写，或人明确关闭。对象仍可阅读 |

同一时刻只有一个会话为「进行中」。Agent 通过 Case 管理工具维护会话表，这些工具不随阶段关闭：

- **列出会话**：返回每个 Case 的名称、所属产品、申请类型、阶段、会话状态、挂起的人工决定、最近更新时间，以及父案件（若有）。
- **创建案件**：新建 Case 与会话，填写名称和所属软件产品，并把它设为激活会话。申请类型固定为发明，领域固定为软件。
- **切换会话**：把当前会话改为待命或保持待人决定，将目标会话设为进行中。激活上下文替换为目标 Case 在其当前阶段允许阅读的对象，以及该 Case 自己的记忆摘要。上一案的记忆不进入新上下文。
- **恢复会话**：人提交决定后，该会话从待人决定变为待命；Agent 或用户将其激活后，从新的门禁状态继续。
- **从布局发起下一轮**：以未覆盖特征创建子 Case，继承这些特征和相关对比文献，父案件记在子 Case 上。已保护特征不作为待挖发明点进入子 Case。子 Case 只继承与这些特征直接相关的父案记忆，并标明来源是父案件。父案其余记忆不复制。
- **结束会话**：仅当回写已完成，或人明确放弃该案件时允许。结束后 Case 对象和长期记忆保留并可阅读，不再接受对象写回或新的记忆写入。

列表中的其他案件只提供上述摘要。特征、发明点、权利要求和该案记忆只在该会话被激活后注入。把未覆盖特征继承到子 Case，只能走「从布局发起下一轮」，不能在摘要层面抄写父案件正文。

### 5.3 循环

1. Harness 注入会话列表摘要，以及激活 Case 的当前阶段、未完成门禁、对象摘要和记忆摘要。
2. Agent 调用一个工具：Case 管理工具、该 Case 的记忆工具，或激活 Case 当前阶段允许的工具。
3. 工具返回结构化结果，或返回校验错误。
4. 阶段工具只更新激活 Case。Harness 判断该 Case 的门禁。
5. 门禁未过则在该会话内继续循环。需要人决定时，只挂起这个会话。Agent 可以切换到其他待命会话继续工作。人提交决定后，该会话可被恢复。

人的决定是一种工具结果。模型不能代替人填写处置或放行字段。写回请求若携带的 Case 标识与激活会话不一致，harness 拒绝该调用，两个 Case 都保持原状。

### 5.4 阶段与工具边界

| 阶段 | Agent 可以写 | Agent 不能写 |
|---|---|---|
| 定界 | 范围卡、初始检索式 | 特征、发明点、申请文件 |
| 汇料 | 技术特征 | 发明点、权利要求 |
| 挖点 | 发明点卡片 | 评估处置、申请文件 |
| 评估 | 区别特征草案、三性 review 所依据的对比关系草案 | 处置结论、三性通过 |
| 交底 | 交底书草案 | 发明人确认、权利要求定稿 |
| 撰写 | 权利要求树、说明书、摘要、附图说明 | 跳过三性定稿、改写人已确认的区别特征 |
| 回写 | 已保护特征、未覆盖特征、布局地图 | 在回写完成前把案件标为结束 |

评估阶段的三性结论由 review 步骤写入，见第 8 节。撰写阶段改动独立权利要求的保护范围后，定稿门禁重新打开，必须再跑一次三性 review。

### 5.5 长期记忆

每个 Case 在创建时得到自己的长期记忆库。已结束的案件仍可按条召回。记忆库记录「为什么这样决定、什么已经被否定、哪些约束必须继续遵守」，领域对象仍是技术方案和申请文件的事实来源。记忆与对象冲突时，以对象的当前内容为准，并在记忆摘要中标出这条冲突。

一条记忆包含：时间、类型、关联对象、正文、来源、是否仍有效。类型取值为：

| 类型 | 写入方式 | 激活时 |
|---|---|---|
| 决定及理由 | 人提交决定后由 harness 自动写入，含角色、结论和理由 | 与当前阶段相关的决定进入摘要 |
| 用户纠正 | 人明确改口或否定某种写法后写入 | 始终进入摘要 |
| 范围约束 | 定界确认的排除项、技术秘密边界、不得写入申请的内容 | 始终进入摘要 |
| 检索与三性结论 | 三性 review 完成或人审放行后，由 harness 写入结论要点 | 评估和撰写阶段进入摘要 |
| 已否定路径 | 被放弃的发明点、被撤回的保护范围、明确不再使用的手段 | 挖点、评估、撰写阶段进入摘要 |
| 问题关闭说明 | 交底开放问题关闭时，由 harness 写入关闭依据 | 交底和撰写阶段进入摘要 |

来源取值为「人」「harness」「父案件」。Agent 可以提议写入「用户纠正」和「已否定路径」，但必须关联到本 Case 的某个对象或某次人的原话。harness 拒绝没有关联的记忆、拒绝 Agent 写入「决定及理由」，也拒绝覆盖或删除已有记忆。要改变旧结论，只能追加一条新记忆，并把旧条目标为不再有效。人可以作废 Agent 提议并已入库的「用户纠正」或「已否定路径」；作废本身再记一条记忆。

激活会话时，harness 注入的是记忆摘要，不是全库。摘要包括：仍然有效的范围约束和用户纠正、与当前阶段相关的最近决定、当前阶段需要避开的已否定路径。更早的条目通过召回工具按对象、类型或关键词查询，查询范围限于本 Case 加上已经标明的父案继承条目。

召回和写入在各阶段都可用，不随阶段工具表关闭。写记忆不改变阶段，也不代替门禁。一条记忆不能把待核实特征改为已核实，不能把三性标为通过，也不能把开放问题标为已关闭。

## 6. 工作流

一件 Case 按顺序经过七个阶段。上一阶段门禁未过，不能进入下一阶段。

### 6.1 定界

输入是课题、产品、目标市场和已有专利包。产出是范围卡：技术领域、产品模块、要保护的市场、明确不挖的部分、本单位已有专利、初始检索式。

不挖的部分包括公知结构、已经公开的方案，以及计划作为技术秘密保留的工艺。后续发明点都落在这张范围卡内。

### 6.2 汇料

输入是设计文档、代码与注释、测试和实验记录、会议纪要、竞品拆解、论文。产出是特征库中的技术特征。

一条特征记录四件事：要解决的问题、具体手段、带来的效果、出处。出处落到文档页码、段落或代码位置。无法定位出处的条目标为「待核实」。

### 6.3 挖点

按「同一技术问题 + 可独立成立的手段」把特征聚合成发明点卡片。手段写成软件步骤、模块之间的数据处理，或可执行的算法规则。效果写成可验证的技术效果，例如时延、资源占用、准确率、一致性或安全性。一张卡片包含：技术问题、一句可成立的核心手段、技术效果及其证据、可替换的下位实施方式、与最接近现有技术的差异点。

只有界面配色、图标或造型，没有软件技术手段的内容，不能收成发明点。纯商业规则或人为约定，同样不能收成发明点。

同一手段只保留一张卡。差异只在参数或场景上的，并入替代方案。能够单独授权的手段拆成多张卡，供后续决定合案或分案。待核实特征不能进入卡片。

### 6.4 评估

对每张发明点卡片做三件事，并跑三性初检（第 8 节）。

- 从智慧芽选定对比专利，标出最接近的一篇，写下区别特征和该区别实际解决的问题。对比专利的查找与选定以 [智慧芽](https://www.zhihuiya.com/) 为入口。检索使用工作台配置的机构账号，该席位最多 16 人同时在线。账号和密码只放在本地密钥配置中，不写入 PRD、仓库或案件对象。
- 标布局位置：核心、外围、防御。核心拦竞争对手的主方案；外围覆盖变体、检测和制造方法；防御防止他人围堵自己的方案。
- 由人给出处置：撰写、补实验后再评、转为技术秘密、放弃。

只有处置为「撰写」且三性初检通过或已有人审放行的卡片进入交底。检索式和对比文献留在评估记录中，撰写和答复审查意见都使用它们。

### 6.5 交底

交底书由发明点卡片展开，面向撰写。固定章节：现有技术方案、对比专利的差异点与不足、发明目的、技术方案、具体实施方式（含替代）、效果与证据、附图说明、开放问题。

「现有技术方案」和「差异点与不足」按对比专利分篇写，不写无法对应到具体专利的笼统缺陷。每一篇都包含：

- 专利标识：公开号或申请号、标题、智慧芽链接。
- 现有技术方案：该专利实际采用的手段，摘录位置落到权利要求项或说明书段落。
- 差异点：本发明的手段与该现有方案相比，多了、少了或替换了哪一个技术特征。
- 不足：该现有专利没有解决的问题，或其手段带来的缺陷。不足要能解释本发明为什么需要那些差异特征。

评估阶段标为最接近现有技术的那一篇必须出现在交底书中。差异点使用的特征要能指回特征库。只写「效果更好」「结构更简单」而不指出特征差异的，这一篇视为未完成。

发明人确认三件事：对比专利的方案摘录是否准确，替代方案是否真实可实施，效果是否有据。任一篇对比专利缺少标识、方案摘录、差异点或不足，或者仍有未关闭的开放问题，不能进入权利要求定稿。

### 6.6 撰写

申请文件的生成顺序固定：

1. 独立权利要求。同一发明点在一件申请里按类别各写一项独立权利要求，必要技术特征相同：方法；装置或电子设备；计算机可读存储介质。计算机程序产品为可选类别。
2. 从属权利要求树，每项对应一个已确认的替代步骤、模块、数据条件或附加技术效果。
3. 说明书。发明内容与权利要求用语一致，具体实施方式覆盖每项从属权利要求，并写明软件在何种设备上执行。
4. 摘要和附图。附图是流程、模块或数据关系，不是外观视图。摘要不引入权利要求中没有的发明点。

一件申请对应一个发明点，或对应一组同一发明构思下的关联点。不另案申请外观设计，也不把同一软件方案拆成实用新型。布局位置为外围的变体默认另案，仍是软件发明。保护范围以评估记录中人确认的区别特征为准。代理人修改范围后，说明书用语与权利要求保持一致，并重新进入三性定稿门禁。

### 6.7 回写

定稿后写回特征库三样东西：本申请实际保护的特征、仍未覆盖的特征、审查中新出现的对比文献。未通过三性的区别特征留在未覆盖列表。布局地图按产品模块展示已申请、技术秘密和未覆盖。下一轮挖掘从「未覆盖特征」开始。

## 7. 领域对象

| 对象 | 内容 | 谁可以拍板 |
|---|---|---|
| 会话 | 绑定的 Case、状态、激活与否、挂起原因 | Agent 可切换；结束须满足第 5.2 节 |
| 范围卡 | 技术边界、排除项、检索策略、已有专利 | 知识产权工程师 |
| 技术特征 | 问题、手段、效果、出处、核实状态 | 工程师确认待核实项 |
| 发明点卡片 | 问题、手段、效果、替代方案、差异点 | 工程师确认拆分与合并 |
| 对比专利 | 公开号、标题、智慧芽链接、方案摘录及位置、与本发明的差异点、该专利的不足 | 人从智慧芽选定并确认摘录 |
| 评估记录 | 对比专利、区别特征、布局位置、处置、三性条目 | 人确认处置；review 写三性 |
| 交底书 | 固定章节与开放问题 | 发明人确认替代方案与效果 |
| 申请文件 | 权利要求树、说明书、摘要、附图 | 代理人确认保护范围 |
| 布局地图 | 已申请、技术秘密、未覆盖，按模块摆放 | 随定稿回写更新 |
| 三性 review 记录 | 见第 8 节 | review 步骤写入；人可附理由放行 |
| 长期记忆 | 决定及理由、用户纠正、范围约束、检索与三性结论、已否定路径、问题关闭说明 | 决定类由 harness 随人审写入；Agent 只可提议纠正和已否定路径 |

核实状态取值为「已核实」或「待核实」。处置取值为「撰写」「补实验后再评」「技术秘密」「放弃」。布局位置取值为「核心」「外围」「防御」。每件 Case 的申请类型都是发明，领域都是软件。创造性使用发明专利的标准。

## 8. 三性 Review

三性检查是 harness 的 review 门禁，与撰写 Agent 分开运行。检查发生两次，规则相同。

- **评估门禁**：对象是发明点卡片。未通过则处置不能标为「撰写」。
- **定稿门禁**：对象是独立权利要求及其从属项。未通过则申请文件不能定稿。

### 8.1 新颖性

使用单独对比。判断独立方案的全部必要技术特征是否已被一篇现有技术完整公开。记录必须指出最接近文献，以及未被该文献公开的特征。

单篇已经覆盖全部必要特征，结论为不通过，退回改范围或改为放弃。没有检索结果，结论为证据不足，不能过门禁。

### 8.2 创造性

只检查新颖性已通过的方案，按三步法记录：

1. 最接近的现有技术。
2. 区别特征，以及这些区别实际解决的技术问题。
3. 现有技术是否给出了将该区别用于该问题的启示。

区别特征、技术问题和启示都要指回特征库出处和效果数据。区别只是公知手段的直接替换、现有技术已有相同启示，或效果没有证据，结论为不通过。

创造性标准是突出的实质性特点和显著的进步。软件方案要能看出区别特征如何用技术手段解决技术问题，并带来技术效果。

### 8.3 实用性

判断方案能否在产业上制造或使用，并产生积极效果。具体实施方式要能让本领域技术人员再现。效果要落到实验、对比或确定的技术机理上。纯概念、不能实施，或效果与手段对不上，结论为不通过，退回交底补实施方式或补证据。

### 8.4 Review 记录

每项三性各写一条：

| 字段 | 说明 |
|---|---|
| 检查项 | 新颖性、创造性、实用性 |
| 对象 | 发明点卡片或权利要求项 |
| 结论 | 通过、不通过、证据不足 |
| 依据 | 对比文献段落、特征出处、实施方式位置 |
| 阻断 | 是否挡住当前门禁 |
| 退回动作 | 改权利要求范围、补实施方式、补实验、改处置、提交人审 |

人可以否决「不通过」，但必须在同一条记录上写下理由。这条人审结果成为新的门禁输入，撰写 Agent 不能覆盖它。

定稿时三项均为通过或已有人审放行，申请文件才进入回写。

## 9. Harness 不变量

每次写回时检查。不满足则拒绝本次工具调用，Case 保持原状。

1. 技术特征必须有出处，否则只能为待核实，不能进入发明点。
2. 发明点必须同时具备问题、手段和效果，才能进入评估。
3. 没有检索结果的新颖性结论只能是证据不足。
4. 新颖性不通过或证据不足时，处置不能为撰写。
5. 创造性只在新颖性通过之后判定。
6. 实用性不通过时，不能进入权利要求定稿。
7. 没有处置为撰写、且三性初检通过或已人审放行的评估记录，不能生成交底书。
8. 交底书仍有未关闭的开放问题，不能定稿权利要求。最接近的对比专利未写入交底书，或任一篇缺少公开号、智慧芽链接、方案摘录、差异点和不足之一，也不能定稿权利要求。
9. 每项从属权利要求在具体实施方式中有对应描述。
10. 独立权利要求的保护范围变更后，原定稿三性记录失效。
11. 三性三项通过或已有人审放行之后，才允许回写。回写必须同时更新已保护特征、未覆盖特征和布局地图。
12. 阶段工具的写回只能作用于激活会话的 Case。Case 标识不一致时拒绝写回。
13. 未激活案件的对象不进入 Agent 上下文。跨案件继承只通过「从布局发起下一轮」完成。
14. 待人决定的会话不能被阶段工具推进。结束会话只在回写完成或人明确放弃后允许。
15. 记忆写入和召回只作用于激活 Case。不能读取或写入其他案件的记忆。父案记忆进入子 Case 时，必须带父案件来源，且只含与继承特征直接相关的条目。
16. 已有记忆只能追加，不能覆盖或删除。人作废某条记忆时，原条目保留并标为不再有效。
17. 记忆不改变核实状态、三性结论、处置、开放问题或阶段。这些仍只由对应对象和门禁更新。
18. 会话结束后，该 Case 的长期记忆仍可召回，但不能新增。

## 10. 功能需求

### 10.1 会话与案件

- 会话列表展示全部 Case：名称、产品、申请类型、阶段、会话状态、挂起的人工决定、父案件、最近更新时间。
- 创建案件时同时创建会话，并激活该会话。申请类型固定为发明，领域固定为软件。实用新型和外观设计不能创建。
- 切换会话后，工作台与对话上下文都变为目标 Case。原会话进度保留。
- 一个案件同时只有一个当前阶段，也只有一个会话。
- 待人决定的会话在列表中单独可见。人提交决定后可以恢复，恢复前阶段工具不能推进它。
- 案件页展示七个阶段、当前门禁和挂起原因。
- 保留每次工具写回、会话切换和人审决定，可按时间查看，便于核对结论从哪次写回产生。
- 从布局地图的未覆盖特征创建子 Case 时，子会话被激活，父案件的已保护特征不进入子 Case 的待挖发明点。与继承特征直接相关的父案记忆以「父案件」来源复制到子 Case。

### 10.2 范围卡

- 编辑技术边界、排除项、已有专利和检索式。
- 定界完成由工程师确认，确认后进入汇料。

### 10.3 特征库

- 从导入材料抽取候选特征，人可改问题、手段、效果和出处。
- 支持按问题、模块、核实状态筛选。
- 待核实项有单独列表，核实后才能被发明点引用。
- 定稿回写的已保护、未覆盖状态在特征上可见。

### 10.4 发明点

- 从已核实特征生成候选卡片，人可拆分、合并和编辑替代方案。
- 卡片展示所引用的特征及出处。
- 一张卡片进入评估前，系统检查问题、手段、效果是否齐全。

### 10.5 评估与三性

- 使用本地配置的智慧芽机构账号检索。配置缺失时不发起登录，只保留人工登记入口。
- 检索后为卡片绑定对比专利：公开号、标题、智慧芽链接、方案摘录及在该专利中的位置。案件中不保存智慧芽密码。
- 对每一篇写明与本发明的差异点，以及该专利的不足。最接近的一篇单独标出。
- 运行三性 review，分别生成三条 review 记录。
- 展示退回动作。人选择处置，或对不通过项写明理由后放行。
- 处置为撰写且门禁通过的卡片进入交底队列。

### 10.6 交底与撰写

- 按固定章节生成交底书草案。现有技术方案、差异点和不足按对比专利分篇列出，开放问题单独列出。
- 缺少对比专利，或某一篇没有差异点、不足或智慧芽链接时，交底完成状态不可用。
- 发明人确认对比专利摘录是否准确，并逐项确认替代方案和效果，或把问题退回为未关闭。
- 按第 6.6 节的顺序生成权利要求树和说明书草案。
- 修改独立权利要求后，界面标明定稿三性已失效，并提供重新 review 的入口。
- 说明书与权利要求用语不一致、或从属项缺少实施方式时，定稿动作不可用。

### 10.7 长期记忆

- 每个 Case 创建时即有空的记忆库，案件页可按时间、类型和关联对象浏览。
- 人提交第 12 节的决定后，对应的「决定及理由」自动出现在记忆库，并在该会话再次激活时进入摘要。
- 范围约束在定界确认时写入，此后每次激活都出现在摘要中。
- 人可以要求记下纠正或已否定路径。无关联对象、也无法关联到人的原话时，这条记忆不入库。
- 召回只返回本 Case 的记忆，以及子 Case 上已标明父案件来源的继承条目。
- 人可以作废 Agent 写入的纠正或已否定路径。决定及理由、三性结论和问题关闭说明不作废，只追加新条目说明后续变化。
- 会话结束后记忆仍可打开和召回，写入入口关闭。

### 10.8 布局地图

- 按产品模块展示已申请、技术秘密、未覆盖。
- 从未覆盖特征可以发起下一轮挖掘，新案件继承这些特征和相关对比文献。

## 11. 交互

用户使用 PatentX 的方式和 Codex 相同：选一个会话，在底部输入框用自然语言说明要做的事，Agent 在对话流里逐步执行，需要人决定时就地弹出确认。用户不先走完一套表单才开始挖掘。

界面分为三栏：

- **左栏**：会话列表。每行是一个 Case，显示名称、阶段、会话状态和是否待人决定。新建会话、切换、恢复都在这里完成。切换后，中栏和右栏整份换成目标 Case。
- **中栏**：当前会话的对话流，底部是输入框。用户可以下达「从这份设计说明里抽特征」「用智慧芽对比这个发明点」「按差异点写交底书」这类任务，也可以中途追加一句纠正。
- **右栏**：当前 Case 的产物。Agent 每写回一次，右栏对应对象立即更新。产物包括范围卡、特征库、发明点、对比专利与三性 review、交底书、权利要求与说明书、布局地图、长期记忆。

对话流里，Agent 的一轮工作展开为步骤：调用了哪个工具、写回了哪个对象、门禁是通过还是被拒绝。步骤可以收起，展开后能看到写回摘要和校验错误。用户从步骤上的对象名打开右栏对应位置。

人工决策是对话流中的确认卡片，挂在触发它的那一步下面。卡片写明待决定的事项、可选结论和必填理由。用户在卡片上提交后，harness 才写入决定并恢复该会话。卡片不能由 Agent 代点。

Agent 正在执行时，用户仍可发送下一条消息。这条消息进入当前 Case 的对话，Agent 在下一步读取。其中属于范围约束、纠正或否定某条路径的内容，同时按第 5.5 节写入长期记忆。

右栏可以改已有对象的可见字段，例如改正文、出处和替代方案。保存时调用与对话相同的工具，并受同一门禁约束。右栏不提供「将三性标为通过」或跳过确认卡片的操作。

## 12. 人工决策点

| 决策 | 角色 | 挂起位置 |
|---|---|---|
| 范围卡确认 | 知识产权工程师 | 定界完成 |
| 待核实特征的出处 | 知识产权工程师 | 汇料 |
| 发明点拆分与合并 | 知识产权工程师 | 挖点 |
| 处置：撰写、补实验、技术秘密、放弃 | 知识产权工程师 | 评估 |
| 三性不通过时的放行理由 | 代理人或知识产权负责人 | 评估、定稿 |
| 对比专利摘录、替代方案与效果确认 | 发明人 | 交底 |
| 独立权利要求保护范围 | 专利代理人 | 撰写 |

挂起期间，该会话的循环停止，确认卡片留在对话流中。其他会话仍可从左栏激活并继续。人在卡片上提交决定后，harness 写入对应字段，并追加一条「决定及理由」。该会话变为待命，被再次激活后从新状态继续，这条决定进入记忆摘要。

## 13. 版本范围

**第一版包含**

- 多会话 Case 管理：列表、创建、切换、挂起、恢复、结束，以及从父案件发起下一轮。
- 每个 Case 的长期记忆：自动记录人工决定，激活时注入摘要，可按对象召回；子 Case 只继承相关父案记忆。
- 仅软件类发明专利。权利要求按方法、装置或电子设备、计算机可读存储介质成组；计算机程序产品可选。
- 七阶段状态、对象存储、阶段工具边界。
- 特征库、发明点卡片、交底书和申请文件草案。
- 评估与定稿两次三性 review，以及人审放行。
- 交底书按智慧芽对比专利分篇写出现有技术方案、差异点和不足。检索账号为机构席位（最多 16 人同时在线），凭证来自本地密钥配置。第一版不把密码写入仓库；未配置凭证时，由人在智慧芽选定后手工登记公开号和链接。
- 定稿回写特征库和布局地图。
- 会话列表、案件对话流和右侧产物栏。交互对齐 Codex：自然语言下达任务，步骤展示在对话中，人工决定用确认卡片提交。

**第一版不包含**

- 官方受理、缴费、审查意见答复的流程托管。
- 外观设计专利、实用新型，以及界面视觉样式、纯商业规则等非软件技术方案。
- 多申请人协作权限之外的组织级流程审批。
- 自动向专利局提交。

审查意见答复沿用同一 Case：新对比文献进入评估记录，保护范围变更重新打开定稿三性门禁。该能力放在第一版之后，数据对象在第一版预留。

## 14. 验收标准

1. 给定一份带页码的设计说明，汇料结果中每条已核实特征都能打开出处；无出处条目不能被发明点引用。
2. 发明点缺少问题、手段或效果时，不能进入评估。
3. 新颖性证据不足或被单篇文献完整公开时，处置无法选为撰写。
4. 撰写 Agent 的工具集合中不存在「将三性标为通过」。
5. 交底书存在未关闭开放问题时，定稿操作被拒绝。未登记智慧芽对比专利，或最接近专利没有差异点和不足时，定稿同样被拒绝。
6. 修改独立权利要求后，原定稿三性记录失效，定稿保持拒绝，直到重新 review 通过或人审放行。
7. 从属权利要求在具体实施方式中没有对应描述时，定稿被拒绝。
8. 定稿回写后，特征库能区分已保护和未覆盖，布局地图与这两类特征一致。
9. 从布局地图的未覆盖特征发起下一轮挖掘时，新案件带上这些特征，且不包含已保护特征作为待挖发明点。
10. 页面操作与对话操作写入同一激活 Case。任一侧产生的评估记录，另一侧立即可见。
11. 同时存在两个以上案件时，切换会话后 Agent 上下文只含目标 Case 的阶段对象。对非激活 Case 的写回被拒绝。
12. 一个会话处于待人决定时，Agent 仍可激活另一个待命会话并推进后者。前者在人提交决定前不能被阶段工具改写。
13. 结束未完成回写、且人未明确放弃的会话时，操作被拒绝，Case 保持原阶段。
14. 在案件 A 中确认「某手段不得写入申请」后，切换到案件 B 再切回 A，该约束仍在 A 的记忆摘要中，且不出现在 B 的上下文里。
15. 关闭案件 A 的会话后再次打开阅读，A 的历史决定仍可按条召回；此时不能向 A 新增记忆。
16. 从 A 的未覆盖特征创建子 Case 后，子 Case 的记忆只含与这些特征直接相关的父案条目，并标明来源为 A。A 的其余记忆不能被召回到子 Case。
17. 仅有一条记忆声称某特征已核实，或某项三性已通过时，特征状态和三性结论保持不变，对应门禁仍然拒绝。
18. 创建案件时不能选择实用新型或外观设计。已创建案件的申请类型为发明，领域为软件。
19. 仅有界面视觉样式或商业规则、没有软件技术手段和技术效果的内容，不能进入发明点，也不能被处置为撰写。
20. 打开工作台后，主界面是左栏会话、中栏对话、底部输入框和右栏产物。用户用一句话开始汇料后，对话流出现工具步骤，右栏特征库同时出现新特征。
21. 评估需要处置时，确认卡片出现在当前对话步骤下。未提交卡片前，该会话停留在待人决定；Agent 不能自行把卡片标成已确认。
22. 右栏修改一条特征的出处后，对话侧立即能读到同一条更新。右栏不存在把三性标为通过的控件。

## 15. 成功标准

- 一件进入撰写的发明点，其独立权利要求的必要技术特征都能追溯到已核实特征。
- 每件定稿申请都有完整的两次三性记录（评估、定稿），结论为通过或带理由的人审放行。
- 下一轮挖掘可以直接从上一件的未覆盖特征开始，而无需重新拆读全部原始材料。
- 多件案件并行时，等待发明人或代理人决定的会话不会挡住其余案件继续汇料、挖点或撰写。
- 隔天重新打开任一案件，Agent 仍能遵守该案已经确认的范围约束、用户纠正和已否定路径，而不依赖当时的对话窗口还在不在。
- 每件进入撰写的交底书都能按公开号打开对应的智慧芽对比专利，并读到该专利的现有方案、与本发明的差异，以及该专利的不足。
- 每件定稿的软件发明都在同一申请中写有方法、装置或电子设备、计算机可读存储介质三类独立权利要求，且三类的必要技术特征一致。不产生外观设计案或实用新型案。
- 用户完成一轮挖掘时，主要操作是在会话输入框里交代任务，并在对话中的确认卡片上做决定。产物从右栏阅读和修订。
